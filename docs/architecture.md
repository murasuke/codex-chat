# アーキテクチャ設計（MVP）

## 1. 目的

社内Webアプリに埋め込めるヘルプチャットボットを提供する。回答はマニュアル情報に基づき、参照URLを1〜3件返却する。

## 2. 構成

1. Crawler Service (`apps/crawler`)
- 単一ドメインをクロール
- `ETag` / `Last-Modified` / `content_hash` で差分更新
- 本文/見出し/画像メタを抽出

2. Indexer (Crawlerに同梱または分離)
- テキストをチャンク分割
- Embeddings生成
- ベクトル検索基盤へ登録
- 画像メタはPostgreSQLへ保存

3. Chat API (`apps/chat-api`)
- 質問受付
- ベクトル検索 + 文脈整形 + LLM生成
- `citations` を1〜3件返却
- 関連画像 `images` を0〜3件返却

4. Widget (`apps/widget`)
- 右下FABアイコン
- クリックでチャットパネル展開
- 非SPAページ遷移を前提に毎ページ初期化
- `sessionStorage` に `session_id` を保持

## 3. データフロー

1. 週次ジョブ開始（cron）
2. クローラーがページ取得、差分判定
3. 変更ページのみ解析・再インデックス
4. ユーザー質問時に類似チャンク検索
5. 回答 + 参照URL + 参考画像を返却

## 4. 参照URL/画像ポリシー

- 参照URLは回答ごとに最低1件、最大3件
- 画像は元サイトURLをそのまま返却し、チャット内でインライン表示
- 画像出典として `source_url` を添付

## 5. スケジューリング

- cron例: 毎週日曜 03:00 JST
- 失敗時は再試行（指数バックオフ）
- 手動再実行エンドポイントあり

## 6. セキュリティ

- 社内利用限定、SSO不要
- APIキーとIP/ネットワーク制御を推奨
- ログには機密情報を残さない
